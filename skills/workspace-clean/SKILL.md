# workspace-clean

Deleting files is easy. Deleting only the files nobody wants is the job. This skill
classifies every candidate by evidence, shows a plan, and removes through the `hk`
engine. The engine:
- moves files to the trash by default;
- re-checks every file before touching it;
- refuses tracked files, `.env*`, keys, `.quest/`, `docs/`, and anything outside the
  item's allowed root.

Engine: `HK="python3 <dir>/../../scripts/hk.py"`, where `<dir>` is the
`Base directory for this skill` that the Skill tool printed.

**Why not `git clean`?**
- `git clean -X` and `-x` delete ignored files, including `.env` and local config.
- `git clean -d` deletes untracked work in progress.

Both are permanent. The recorded agent incidents that destroyed home directories were
"cleanup" through `rm -rf` on unresolved variables in generated scripts. Use `hk`; if it
refuses something, report the refusal.

## What gets found, and where it lands

| Kind | Level | Class | Why |
|---|---|---|---|
| `file.junk`: untracked, junk-named (`*.bak`, `*.orig`, `*_old.*`, `*_v2.*`, `* copy.*`, `tmp_*`, `scratch*`, `debug*.log`, `*_SUMMARY.md`, `nul`) | C2 | S1 if the session's ledger created it, else **S2** | the name alone is weak evidence |
| `file.untracked-work`: the session created it, uncommitted | C1 | finding | real work to commit, not junk |
| `file.junk-ignored`: ignored and junk-named (`*.log`) | C3 | S1 | ignored and junk-named: safe to trash |
| `tmp.attributed`: `$TMPDIR` entries with a `[tmp] prefixes` prefix, idle past `max_age_days`, or recorded in the ledger | C4 (C2 for ledger) | S2 | test suites that leak temp dirs |
| `dir.build` / `file.build`: ignored build and dependency outputs | C4 | S2 | regenerated by install/build |
| `scratchpad.old`: Claude Code session scratch dirs | C4 this project, C5 all | S2 | the current session's is protected |
| `file.ignored-other`: ignored, not a known output (IDE settings, local config) | C5 | **S3** | could be someone's configuration |
| `file.untracked`: untracked, not ignored, not junk | C5 | **S3** | possibly unsaved work |

```bash
$HK plan --level C4 --domains files,tmp --chosen-by "user asked to free disk space"
```

## Judgement the engine can't make

Before approving a junk batch, **look**. For each `file.junk` item, check:
- **Is it imported, referenced, or run?** `git grep -n "<basename-without-ext>"`. A
  `parser_v2.py` that `main.py` imports is the new parser, not junk: take it out of the
  plan (`--only` the rest) and tell the user.
- **Is it the only copy of something?** A `notes.bak` whose content differs from any
  tracked file may be the user's draft. Peek at small files (`head -20`); don't read large
  ones.
- **Is it recent and from this session?** The ledger says so when provenance capture is
  on. Otherwise the file's age next to the session's start is a hint, not proof.

For **temp leaks**, fix the cause as well as the symptom:
1. Identify the producer (the prefix usually names it: `lore-readme-*`,
   `opum-e2e-ws-*`).
2. Add the prefix to `[tmp] prefixes` in `.housekeeping.toml` so later passes find it.
3. Tell the user which test suite leaks and suggest a follow-up task (a missing
   `afterEach` cleanup or `tempfile.TemporaryDirectory`). If the suite belongs to another
   repo, it goes in that repo's findings; don't edit it from here.

For **build outputs**, removal is regenerable, not free. Say what will need
reinstalling: "node_modules (1.1 GB): the next `npm ci` takes about 40 s".

## Applying

1. Show the plan table.
2. **S1** runs without asking.
3. **S2** needs one batch approval. Use AskUserQuestion with the count and size, and
   recommend yes when the batch is what was asked for.
4. **S3** needs each item confirmed by name. Use AskUserQuestion with `multiSelect`,
   nothing preselected.

```bash
$HK apply <plan.json> [--approve-s2] [--confirm id1,id2] [--only ids-you-kept]
```
Then report:
- trashed vs permanently removed (build outputs are `rm`: regenerable, and trashing
  gigabytes of `node_modules` only moves the problem);
- reclaimed bytes;
- the journal path.

## Clean room (C5)

A clean room means the checkout matches a fresh clone. The only exceptions are the
`[cleanroom] keep` list (default `.env`, `.env.local`) and the protected set.
- Every other ignored or untracked path is planned, most of them as S3.
- **Commit or stash real work first.** The Land phase exists for this.

After clearing, the tidy skill runs the rebuild-from-scratch proof.

## Never

- Remove a tracked file. That is a code change: commit the deletion.
- Remove anything under another repository's checkout.
- Remove `.git/`, `.quest/`, `.lore/`, `docs/`, `.env*`, keys, or `.pi/`, whatever it
  looks like.
- Delete the current session's scratchpad. It may hold outputs the user still wants to
  see.
